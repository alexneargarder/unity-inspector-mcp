# Animation capture

Two halves: `lib/animation-capture.js` (host side, driven by the `capture_animations` MCP tool) and `lib/animation-capture/animation-capture.cs` (in-game script). The host side loads a level, swaps the bro, waits until the bro can be swept, runs the script, waits for its `done`/`error` sentinel, and writes `states.json` and `report.md` (the comparison against the state list) into `out`. The in-game script writes one PNG strip per state (frames left to right), `capture.json` recording the sheet cell each frame addressed and what the level did, and the sentinel into `gameOut` — the same directory, named the way the game's filesystem sees it.

## Running a sweep

`capture_animations` is the tool; it runs on the server's own client, so the sweep goes to whatever target the server is pointed at.

```json
{ "level": "1:0", "bro": "Drunken Broster", "out": "/tmp/capture" }
```

- `out` is the absolute directory the strips, `capture.json`, `states.json` and `report.md` land in. The prep step deletes every `.png` in it, so a directory that already holds files is only accepted when it holds the `.capture-animations` mark an earlier sweep wrote there, with the tool's own text in it; a `states.json` of the user's own does not count. An empty or missing one is always fine. A directory the server cannot create or write, and a state list that is missing or not JSON, are tool errors naming the path.
- `level` (`"CAMPAIGN:LEVEL"`) loads a campaign level first and waits, up to `timeout`, until `game_state` reports a level in play (`isInGame`) with the asked-for `levelIndex`, not finished, and that player alive: `go_to_level` replies once any slot's bro is alive, or a cutscene holds the new level. An out-of-range campaign or level index is `go_to_level`'s own refusal and fails the run.
- `settle` (seconds, default 3, only used with `level`) waits after the level reports its player. The player goes live about a second before the world renders, and a sweep started in that gap captures nothing.
- **A cutscene's pause** (`CutscenePause`) is pressed past before any swap, since a bro swapped in under it is lost and respawned. A bro's intro, played when a load spawns a bro in `yetToBePlayedUnlockedHeroes`, holds until a key: on a level whose bros arrive by transport it holds the bro on it, and `go_to_level` answers at once with `cutscene: "CutscenePause"`, which the tool presses past before the level wait; on one whose bro spawns straight in it starts about half a second after `go_to_level` replies, inside the default `settle`. So with `level` or `bro`, one `game_state` after the settle (with no `level`, before the swap) looks for one and is also the swap's snapshot. Either way, while it reads `CutscenePause` the tool presses `start` for `player` through its own client, as `simulate_input` sends it, again whenever the pause outlasts a press by 3s (`CUTSCENE_REPRESS_MS`; the game ignores a skip in a cutscene's first second), up to `timeout`; after the look it then waits `settle` again on the live game (3s without a `level`) and looks once more. A `settle` shorter than the intro's start misses it, and the readiness wait refuses it. Without a `level` the readiness wait also presses one that started after the swap, then waits 3s plus `swapSettle`. The report's `Cutscene dismissed before the sweep` line and `summary.cutscenePresses` count the presses, and a wait that runs out names them; any other pause is the caller's, never pressed.
- `bro` swap: the tool snapshots the slot and calls `swap_bro`; only a refusal with `reason: "unreachable"` (locked, filtered, off the IronBro roster) is retried with `ignoreUnlocks`, and every other refusal fails the run with the first reply's error. A bro swapped in the second way is not Swap Bros Mod's selection, so a respawn would bring back the selection in his place. The slot is then polled until it reports a live character: when the reply's `objectName` names a character different from the snapshot, liveness is all that is left; with no name, the name must differ from the snapshot; an empty slot beforehand takes anything alive. A reply naming the snapshot's own character is `swap.alreadyHeld` and is not polled.
- `swap_bro` itself fails a swap that leaves the slot holding another bro, on the roster name it replies as `broName`. Every landed swap, the already-held one included, is then confirmed with `list_bros {playerNum}`: its `currentBro` is the roster name `bro` speaks (BroMaker's own name, else Swap Bros Mod's display name), compared without regard to case. A slot holding any other bro — a BroMaker substitution that left plain Rambro — fails the run before anything is swept, and `swap.currentBro` is the name it confirmed.
- `swapTimeout` (seconds, default 15): if the slot never reports the change, the run fails without sweeping and writes no `report.md` and no `capture.json`.
- `swapSettle` (seconds, default 2, only used with `bro`) waits after the swap is confirmed. `swap_bro` answers while the old character is still the one being drawn, and a sweep that freezes the clock there strips the wrong bro. The script refuses to start, as an `error` naming the old rig, when the rig the swap recalled is still drawn in the crop at sweep start.
- Before the script is sent the tool polls `game_state`, up to `timeout`, until the bro can be swept: a level in play, not finished, `pauseState` `UnPaused`, the slot's `state` `alive` and `piloting` null. The `timeScale` it reads there is the speed restored if the script cannot be unloaded. `Main()` then refuses, as a failed `execute_script` the tool answers at once, a pause, a cutscene, a dead bro, a piloting one, one other than the requested `bro`, and one the level has not released yet (on the level-start helicopter, disabled or inactive) — raise `settle` for the last.
- `states` is an array of state lists in layer order (a single string is taken as one layer) and defaults to `base-states.json`. A relative name resolves under `lib/animation-capture/states/` and must stay inside it; an absolute path is used as given. Layers merge by name, later files winning: a same-name entry replaces the earlier one outright and keeps its position. Names whose strip files would collide (`a b` and `a_b`, `Run` and `run`) fail the run.
- `only` (state names) sweeps just those, taken from the merged list in its order; `includeLethal` still applies to them, and a name the merged list does not have fails the run. `states.json` and the report cover the filtered list.
- `gameOut` is `out` as the game's filesystem sees it (default: `out`), and must be absolute in either path style (`/...`, `C:\...`, `\\server\...`). Set it whenever the two path spaces differ — a Proton or WSL install. A wrong one surfaces as the script's `state file not found` refusal, which `execute_script` returns at once.
- `allowSideEffects` lets swept animations fire their real specials and attacks. Without it, the swept bro's own `UseSpecial`, `UsePockettedSpecial`, `PerformKnifeMeleeAttack`, `PerformPunchAttack`, `Land` (a pinned airborne state lands every step and steps on the sand and falling blocks underfoot), `TriggerFlexEvent` (flex powers, Rogueforce perks), `FireWeapon` and `ReleaseHeldObject` are skipped for that character only, through its most-derived declaration, and game-wide every overload of the `Map` and `MapController` methods that damage, kill or stun units, damage terrain, hatch alien eggs or deflect projectiles. On `Map`: `HitUnits`, `HitAllLivingUnits`, `HitClosestUnit`, `HitDeadUnits`, `HitHellUnits`, `HitLivingHeroes`, `HitLivingUnits`, `HitUnitsWithArrow`, `WhipUnits`, `KnockUnits`, `KnockMooks`, `KnockAndDamageUnit`, `ExplodeUnits`, `FivePointPalmExplodingHeartTechnique`, `DecapitateUnits`, `HeadShotUnit`, `InseminateUnits`, `StunUnits`, `StunMooks`, `BlindUnits`, `TearGasUnits`, `FreezeUnits`, `PanicUnits`, `BurnUnitsAround_Local`, `CrushUnitsAgainstWalls`, `CrushUnitsAgainstWallsHorizontal`, `CrushUnitsAgainstWallsVertical`, `RollOntoUnits`, `HurtWildLife`, `BurnBlocksAround`, `BurnDamageBlock`, `BurnLargeObjects`, `DamageBackground`, `DamageDoodads`, `DamageStaticDoodads`, `DamageDoodadByTag`, `DisturbAlienEggs`, `DeflectProjectiles`; on `MapController`: `DamageGround`, `DamageGroundLocal`, `DamageBlock`, `Damage_Local`, `Damage_Networked`, `BurnUnitsAround_NotNetworked`, `BurnGround_Local`. A skipped call answers its result type's default and is counted on the state's `suppressed`. With side effects allowed the same `Map`/`MapController` set runs and is counted on `damageCalls`, with `hits` the true answers of the ones that return a bool. Every shock wave `EffectsController.CreateShockWave` returns during the sweep, game-wide, is retired through its own `EffectDie` as soon as it is returned rather than skipped: `BroBase.Land` writes to the returned wave.
- `includeLethal` also sweeps the states marked `lethal`. Without it they are left out of the sweep and listed as excluded in the report.
- `timeout` (seconds, default 60) bounds each wait — the level, the readiness — and a sweep that makes no progress: every state rewrites `capture.json`, and each rewrite moves the sweep's deadline on, so a long list on a slow display runs to the end. `player` (0–3, default 0) is the player index captured. `box` (1–256) is the world-unit half-size of the crop box, each strip cell being `2*box` px; unset, the script's own default of 24 applies and `params.box` records it, and the script refuses a box whose widest strip would pass the GPU's texture size limit.

The reply is a JSON object. `success` is true only when the sentinel was `done` and no state errored inside the sweep — a cell mismatch is a finding, not a failed run. `status` is `done`, `error`, `timeout` or `game-gone`; `message` carries the outcome's text (with the game log's `animation-capture` lines appended on a timeout) and is null on `done`. `report` is the Markdown, the same text `report.md` holds; `paths` names `out`, `report`, `capture` (null when the game wrote none) and `states`; `summary` carries the counts the report's bullets do (`captured`, `skipped`, `excluded`, `mismatches`, `errors`, `contributionFailures`, `emptyCellFrames`, `carriedGunFrames`, `retiredObjects`, `levelChangeStates`, `firstLevelChange`, `complete`, `cutscenePresses`); `stateErrors` lists the first 20 messages from `capture.json`, with `stateErrorsOmitted` counting the rest, all of which are in `report.md`; `swap` is null with no `bro` and otherwise `{ requested, slot, alreadyHeld, currentBro }`; `logTail` is the formatted tail on a timeout and null otherwise. `report.md` and `capture.json` land in `out` whether or not the caller is still waiting.

A run that never reached the sweep — another sweep live in the game, a state list that fails validation, a level that never comes into play, a swap that never lands or lands on another bro, a bro that never becomes sweepable, a script that fails to compile or refuses to start — comes back as a tool error with no report.

A sweep holds the game exclusively for its whole length. The server checks for another sweep and records its own with nothing awaited between, so two calls in one turn cannot both start, and while it runs every tool that could change the game is refused — `launch_game`, `wait_for_game`, `run_test_script`, a second `capture_animations`, `set_game_speed`, the level, input and player tools, `execute_code`, `execute_script`, `unload_script`, `trace_spawns`, a highlighted `take_screenshot` — with only `stop_game` and the tools that only read let through. `stop_game` is the escape hatch: the level, swap and readiness waits and the sentinel wait all watch the game process and end at once as `game-gone`. A cancelled call wakes from whichever wait it is in, sends no further setup command, and releases its claim or tears the game down as a failed one does. A run claims the game before it changes it: right after its `ping`, one `execute_code` — one main-thread action, so two servers' claims cannot interleave — reads the `AppDomain` slot `UnityInspector.AnimationCapture.Live` and, when it holds neither a sweep whose object is still alive nor another run's unexpired claim, sets it to this run's claim: a token of its own, its `gameOut`, and a lease ending when every wait and command the setup can spend has run out (`claimLeaseMs()`), so a server killed during setup holds the game only that long. A slot that is held fails the run naming that sweep's directory, with no level loaded, no bro swapped and `out` untouched. The token goes to the script as its `claim` argument, and `Main()` replaces the claim with the sweep itself; a run whose setup fails, or whose script refuses to start, releases its claim — only while the slot still holds its token — and so does a server stopped during setup. `Main()` refuses on the same rule, and also when `bro` was given and the slot's bro, by the roster name `list_bros` reports, is another. Each server sends the script under its own name, `animation-capture-<pid>-<hex>`, since the mod restarts or replaces a loaded script of the same name. A server stopped mid-sweep unloads the script on its way out, and sets the speed it read before the sweep only when the unload failed, so an interrupted sweep does not leave the game frozen — unless that teardown overruns the wrapper's grace period. The sweep's own teardown does the same: the script puts the clock back itself when it unloads.

A state that errors mid-sweep does not abort the run. The bro is restored as after any state, the record is filed with `skipped: "error: …"`, the message goes into `capture.json`'s `errors`, and the sweep moves on. An exception's message is followed by `at <Type>.<Method>`, the method that threw it, so the game's code is told from the capture's, and its whole trace goes to the UMM log through the script's logger. The report lists it under Skipped as `errored (see Errors)` with the message once under Errors, and the reply's `success` is false. A state skipped because its `requires` flags do not hold is not an error. An `after` method that throws leaves the state captured and compared, but the message is filed on the record as `afterError` and pushed into `capture.json`'s `errors`.

## The tool on the server

- **`capture_animations`** is server-side orchestration over `lib/animation-capture/animation-capture.cs`, Node-only like `run_test_script`: `runCapture(options, unityClient, { sleep, pollMs, resolveLog, isRunning, sweep, signal })` in `lib/animation-capture.js` sends every command through the server's own client, so the sweep follows the target. The handler validates the arguments — waits in seconds as `wait_for_game` takes them, an absolute `out` only ever cleared when it carries the `.capture-animations` mark an earlier sweep wrote, an absolute `gameOut` in either path style, `box` at most 256, `only` a list of distinct names, relative `states` names resolving inside `lib/animation-capture/states/` — and passes `{ resolveLog: resolveLogFile, signal, sweep }`: the log resolver is where a timeout's tail comes from, and the signal is what makes a cancelled sweep stop (see Cancellation in `connection.md`). A timeout's tail (`captureLogTail()`) is the last 20 `animation-capture` lines `resolveLog` chose, read backwards over at most 4MB and only past `markCaptureLog()`'s mark, the file's end when the sweep started, unless the game since rewrote it. A failure before the sweep is a thrown tool error, a missing state list or an output directory it cannot write named in plain words; a sweep that ran answers `success`, `status` (`done`/`error`/`timeout`/`game-gone`), `message`, `report`, `paths`, `summary`, `stateErrors` (the first `CAPTURE_REPLY_STATE_ERRORS`, 20, with `stateErrorsOmitted` counting the rest), `swap` and `logTail`. The script and its state lists live under `lib/`, outside `scripts/` altogether, so `list_scripts`, its catalog resource and `list_test_scripts` never see them and this tool is what runs them
- **A sweep is server state, held exclusively.** `index.js` records it module-level (`activeSweep`) once its arguments are read, with nothing awaited between its refusals and the record, so two calls in one turn cannot both pass them, for the sweep's whole length, the sentinel wait included, and only the call that set it clears it, in a `finally`. `refuseDuringSweep()` in `callTool()`, once before a call's target wait and again after it, and after `execute_script`'s and `unload_script`'s file reads, so a call sent in the sweep's turn cannot pass it before the record, refuses every tool outside `SWEEP_SAFE_TOOLS` while it is set — `stop_game` and the tools that only read, and `take_screenshot` without a highlight — so `run_test_script`, `simulate_input`, `set_game_speed`, `execute_code` and the rest cannot move the pinned bro or the clock under it; `refuseWhileInFlight()` gives `launch_game` and `wait_for_game` the same refusal. The refusal names the sweep's `out` and the budget it has left, `claimLeaseMs()` plus `timeout` from its start, which each finished state extends. A running `run_test_script` is server state the same way, recorded for its whole length, waits between steps included, and `capture_animations` is refused while one runs, naming the script, and while a `launch_game` runs, which `callTool()` counts in `launchesRunning` before its first await. `stop_game` is let through as the escape hatch: the level, swap, readiness and sentinel waits all poll `isGameRunning` and end as `game-gone` within one poll, skipping the teardown rather than sending it to nothing. The script goes to the game as `SCRIPT_NAME`, `animation-capture-<pid>-<hex>`, one per server process, since the mod restarts or replaces a loaded script of the same name. Another server's sweep is learnt through an `AppDomain` slot, every compile being its own assembly with its own statics: right after its `ping`, `runCapture` checks and claims it in one `execute_code` (`claimCode()`, one main-thread action) — refused, naming the holder's directory, while the slot holds a live sweep or another run's unexpired claim — before it touches `out`, loads a level or swaps a bro. The claim carries a per-run token, `gameOut` and a lease of `claimLeaseMs()`, the setup's whole budget; the token reaches the script as `claim`, `Main()` replaces the claim with the sweep, and `releaseClaim()` gives it back, token permitting, on a setup or script start that failed or was cancelled and from `shutdownServer()`. `liveRule()` and the script's `LiveSweep()` are one rule, and `Main()` also refuses a slot holding another bro than `params.bro`
- **The shutdown teardown**: every shutdown trigger (see `game-process.md`) delegates to the exported `shutdownServer(reason, { exit })`, which releases a claim still held during setup and, once the script was sent, runs `teardownGame` with the sweep's `scriptName` and `restoreSpeed` (the `timeScale` `game_state` reported before the sweep), each command budgeted at 800ms, alongside the creation-claim wait (see `owner.pid` in `instances.md`); it gives them 2s together and then exits regardless, logging that the game may still be frozen when the teardown overran. `teardownGame` sends `set_game_speed` only when `unload_script` failed, since the script restores the clock itself as it unloads. A sweep holds the game clock at zero with the capture script's patches installed, and the wrapper sends SIGKILL 3s after its SIGTERM, at a restart and at session end alike

## State lists

A state list names the animations to sweep, how to reach each one, and how many frames it has. `base-states.json` covers the animations `TestVanDammeAnim` and `BroBase` share — every animation a stock or BroMaker bro inherits, apart from the gestures other than Flex and the dance, which the game never plays for a player's bro. Those are in `unplayed-states.json`, swept by layering it after the base list: `states: ["base-states.json", "unplayed-states.json"]`. A per-bro list (`drunken-broster.json` is the worked example) carries only what differs: its own states plus any base entry it must restate.

The file is either a bare array of entries or an object with a `states` array. The object's other keys (`schema`, `name`, `source`, `note`) are documentation; nothing reads them. The `states.json` the tool writes into `out` is `{ params, states }`, and the script copies `params` into `capture.json`.

Merge semantics: `states` is one entry per layer, base first. A later entry whose name already exists replaces that entry outright and keeps its position — restate the whole entry, never a patch over the base one. Restate a base entry whenever the bro overrides its dispatch: `special_new` on a bro whose `AnimateSpecial` steps `usingSpecialFrame` instead of `frame` needs its own entry, or the base one drives a field the animation never reads. New entries append unless they name `insert_before`.

The `setup` below is abridged; the real entry in `base-states.json` pins every field its `note` names.

```json
{
  "name": "running",
  "requires": { "useNewFrames": true },
  "setup": { "actionState": "Running", "ducking": false, "dashing": false, "health": 3, "gunFrame": 0 },
  "step": { "field": "frame", "values": [0, 1, 2, 3, 4, 5, 6, 7] },
  "expect": { "sheet": "main", "row": 2, "cols": [0, 7] },
  "note": "ChangeFrame :4075-4078 -> AnimateRunning :3522; ..."
}
```

- **`name`** — required, unique. Names the strip file (`running.png`) and the report entry.
- **`setup`** — an object of fields pinned on the character to steer `ChangeFrame` to this animation. Values are booleans, numbers, or an enum member name as a string; any other shape is refused before the sweep. Field names resolve against the character and its base classes; `frame` and `actionState` are properties over `_frame` and `_actionState` and resolve to those. The whole bro is restored when the state ends, so a field is named here only to pin it. A state whose gun write `ChangeFrame` gates on `gunFrame <= 0` pins `gunFrame: 0`, so its gun cell is drawn by the step and not carried over.
- **`before`** / **`after`** — optional lists of parameterless instance methods called on the character, for states reachable only by having it swap an object reference for itself. `before` runs once, after `setup` is pinned and before the first step; `after` when the state ends, after the bro is restored and on any error teardown, and the bro is restored again after it. Either can be given alone: `after` is also how a state undoes what its real side effects left outside the bro, as `special_new` in `drunken-broster.json` calls `BecomeSober` for `DrunkenCameraManager`'s static list. Example: `running_holding_item` in `drunken-broster.json` uses `before: ["SwitchToHeldItem"]`, `after: ["ClearHeldItem"]`.
- **`insert_before`** — optional, on a layer entry: place the new state ahead of the named one instead of appending. The named state must already be in the merged list when this entry is processed, or the run fails with a usage error. Ignored when the entry restates a state already present.
- **`step`** — the field the frames are driven with and the values to drive it through. `field` defaults to `frame`; countdown-driven animations name their own counter (`chimneyFlipFrames`, `rollingFrames`, `ladderClimbingTransitionFrames`, `flexSpecialFrame`, `inseminatedCounter`, `gunFrame`). `setup` is re-applied before each value, so an animation that clears its own driving flag partway through still runs its full span.
- **`step.call`**, **`step.before`**, **`step.after`** — methods the capture calls on every step right after `ChangeFrame`, in the same frame with nothing between, the order the game's `Update` runs `RunGun` after `ChangeFrame` (`TestVanDammeAnim.cs:1350`); `step.before` pins fields just ahead of the calls and `step.after` just after them, and all three are restored with `setup`. A call is a parameterless instance method, or one taking the single object the state was provided (`AttachToZipline`). This is how cells written outside `ChangeFrame` are drawn: the firing states pin `gunFrame` one above the cell and `gunCounter: 0.04` (over `RunGun`'s 0.0334 threshold), call `RunGun`, and put `gunCounter` back to 0 so the bro's own `Update` does not step the gun again before the frame is read; `hanging_one_armed` calls `StartHanging`, `zipline_hanging` `AttachToZipline`. A per-bro `RunGun` override (Jason's, stepping `gunFrame` 7 to 0) is reached the same way from a per-bro entry.
- **`provide`** — optional, `ladder` or `zipline`: an object the level would supply, given to the state for its length and removed when it ends. `ladder` is a `BoxCollider` on the `Ladders` layer 16 to 40 units above the bro, where `IsNearbyLadder` probes and clear of the downward rays the bro casts for the ground; `zipline` an inactive horizontal `ZipLine` 128 units wide centred over the bro, with its lists empty, pinned as `attachedToZipline` on every step — inactive, it never runs `Start` or `Update`. Neither renders, so neither reaches a crop, the retire pass or `levelChanges`.
- **`expect`** — the sprite-sheet cells this animation should address: `row`, and either an inclusive `cols` range walked one column per step in the order given (`[3, 0]` walks 3, 2, 1, 0), or `col`, a held cell addressed on every step; `sheet` is a display label. `row` and `col` are the sprite's `lowerLeftPixel` floor-divided by its own cell size, with no offset applied on either side: take a new state's values off a capture run rather than deriving them. A `cols` span must be as long as `step.values`. The comparison is on `row` and `col` alone, so a state walking the right cells of a *different* texture still reports ✓; read `texture`, `texId` and `texW`/`texH` in `capture.json` when a sheet swap is the point. A cell recorded `written: "carried"` never satisfies an expectation: it is left over from before the step, not drawn by it.
- **`expectGun`** — optional, same shape over the gun overlay, sheet defaulting to `gun`. A state stating both matches only when both walks do.
- **`requires`** — an object of layout flags that must hold on the live character for the animation to be meaningful (`useNewFrames`, `canAirdash`). When they do not hold the state is recorded as skipped with the flag and its actual value — not an error.
- **`knownMismatch`** — optional reason the state addresses less than its full `expect` span, for one-shots that clear their own flag on the last frame and re-enter `ChangeFrame`. It excuses only the *last* step: every earlier step must still walk the expected columns in order. It is ignored when the state's `expectGun` walk failed and on a single-column span.
- **`lethal`** — optional, `true` when entering the state reads as a death, with `lethalReason` saying why. Pinning `actionState: Dead` with `health: 0` calls neither `Death()` nor `ReduceLives()`, and the respawn countdown subtracts the frozen clock's zero, so the game itself takes no life and respawns nothing during the sweep; a BroMaker hero runs its own `OnDeath` when it sees `actionState` Dead. Excluded from the sweep unless `includeLethal`.
- **`note`** — where the dispatch and cell arithmetic live in the decompiled source, plus the state's known limitations. Bare `:NNNN` line references are `TestVanDammeAnim.cs`; other files are named.

## Unreachable states

An animation needing an object reference the character can install itself is reachable through `before`/`after`, and one needing a ladder or zipline through `provide`. `unsupported` is for the rest — a reference only the world can supply, or a code path `ChangeFrame` never reaches. Such an entry carries an `unsupported` reason instead of `setup`/`step`:

```json
{
  "name": "ledge_grapple",
  "unsupported": "unreachable from ChangeFrame",
  "note": "ChangeFrame's Jumping arm tests ledgeGrapple at :4154-4157 and routes it to AnimateRunning ..."
}
```

Keep these in the file so the tool reports them instead of leaving a silent hole in the coverage.

## In-game capture

`animation-capture.cs` does not read the backbuffer: `ReadPixels` off the screen comes back as zeroed memory for seconds after a level load and whenever the window is not being presented. Each step points every camera that draws to the screen at one `RenderTexture`, in depth order, renders them itself, and reads the crop back from that. A state whose crop was inside the screen and still read back all-zero is recorded as a `blank capture` error.

Each on-screen frame is also checked for the character itself: the scene is rendered again with every enabled renderer on an active, non-zero-scaled part of the character switched off, a part being what his snapshot found under him, so a child a state spawned does not count as his, and the two crops are compared. A frame gets one of three verdicts in `capture.json` (none when offscreen): `contributed: true` when a pixel differs; `contributed: false, cellEmpty: true` when none does and every cell it addressed — the body's, and the gun's while its object is active — has no opaque pixel on the sheet (read by blitting the sheet into a render texture, cached per cell), which is not an error; and `contributed: false` otherwise. Every on-screen frame also carries `bodyCellEmpty`, and `gunCellEmpty` while the gun is active, whatever the verdict, and the report counts and lists those frames, so a blank cell on a custom sheet shows even when the gun drew. A state's failing frames are filed as one error per reason, `state '<name>': the character's renderers contributed no pixel to the crop on N/M on-screen frames (frames 0-7,9)` (or `the character has no enabled renderer …`), followed by why when a failing frame's cell could not be read, as with one off its sheet: `: cell 32x32 at 0,384 lies outside the 1024x256 sheet '…' (and 23 more)`; a state already filed as a blank capture gets none. The report gives each state's figure as `contributed/on-screen (K empty)`.

Each frame records `gunFrame` after the step, and its `body` and `gun` cells a `written` value: a postfix on `SpriteSM.SetLowerLeftPixel` notes who last moved each sprite between the step and its readback — `capture` (the capture's own `ChangeFrame` and step calls), `game` (the game's own update in between), or `carried` (nobody: the cell is left over). The report counts the frames whose active gun cell was carried and lists them per state.

The overlap probe runs once at sweep start, after the clock is frozen: it records up to 24 other renderers drawing in the crop as `overlapProbe`, and stops the sweep only when one hangs under a recalled rig (`recalling`, or `actionState` Recalling) — the bro a swap leaves behind. A companion, another player's hero, a piloted vehicle, a summoned ally and every other unit are recorded, not refused.

The held clock never lets an effect a state spawns animate out, so one frame after a state ends the sweep retires three sets: every pooled effect the game took from its pools since the last cleanup (a postfix on `EffectsControllerPool.Request`), every child under the bro outside the transforms his snapshot took, a respawn's retaken one included, wherever it is and whether or not it draws, and every other object drawn across the crops the state used that was not there at sweep start, then any pooled effect that retiring those spawned in an `OnDisable`, as a real `PredabroSpear` does. A pooled effect goes through its own `EffectDie` back to its pool; anything else is deactivated, never destroyed. Units, cameras, the reaction bubbles and the sweep's own object are kept, as is anything under one, but under the swept bro only the parts his snapshot took and a unit or reaction bubble a state parented there. Each record's `retired` entries are `{ name, count, source, pooled, types, firstSeenStep }` — `source` `requested`, `child` or `crop`, `types` the component type names on the object, `firstSeenStep` the step that requested it — and any such object still drawn in a state's first crop is that state's error.

The level is snapshotted at sweep start, whole map: every `Map.blocks` and `Map.backGroundBlocks` cell (instance id, name, health, destroyed, collapsed, disturbed), every `Map.units` entry but the swept bro (health, dead), and every `Map.destroyableDoodads` and `Map.staticDoodads` entry (health, isDead, collapsed). At each state's retire pass, before anything is retired — and at once for a state that failed before its frames or was skipped — it is diffed against the last snapshot, the delta goes on the record and the snapshot is retaken. Every record carries:

```json
"levelChanges": {
  "blocks": [{ "layer": "foreground", "col": 12, "row": 3, "name": "DirtBlock5(Clone)", "change": "destroyed", "health": [10, 0] }],
  "units": [{ "id": -1234, "name": "Mook(Clone)", "change": "killed", "health": [3, 0] }],
  "doodads": [{ "id": -5678, "name": "Grass(Clone)", "change": "destroyed", "health": [1, null] }]
}
```

Arrays are empty when nothing changed. A block is `destroyed`, `collapsed`, `damaged`, `disturbed` (a sand or falling block set to fall, which happens once the clock runs) or `added`; a unit `killed` (dead, at no health, or `destroyed`, a gibbed one included, whose object the game has already destroyed), `damaged`, `removed` (left `Map.units` without dying) or `added`; a doodad `destroyed` (dead or collapsed, in its list or out of it, or out of it with no health left, as a smashed `ClonePod` is), `damaged`, `removed` (left its list with none of those) or `added`. `health` is `[before, after]`, null on a side with no object. Beside it each record carries `suppressed` and `damageCalls` (`[{ method, calls }]`, `hits` on the latter), and when they happened `clockDisturbed`, `deltaRepaired`, `nonFinite` and `sceneChanged`. The report's summary names the first record with a change (`First level change: <state>` or `none`), and `## Level changes` and `## Damage calls` list them per state.

Game code sets the clock too — a time-stop ramping back, an offline pause toggle, a cutscene — so the sweep checks it every `Update` and `LateUpdate`, puts it back to zero, and files `clockDisturbed: <value>` and an error on the state it happened in. It records the scene and `Map.Instance` at sweep start; a level load or restart mid-sweep errors the state it lands in and every later one with `the scene changed during the sweep`, marks their records `sceneChanged`, and skips the retire, leak and level passes, which would otherwise read the new level's every object as the sweep's.

`capture.json` is `{ params, complete, bro, states, errors }`, rewritten after every state with `complete: false` and once more with `true` at the end, and written once more on an unload mid-sweep, so a timeout or interrupted sweep keeps every state it finished: the report then says `Capture incomplete` and lists the rest under Never reached. `params` is `allowSideEffects`, `includeLethal`, `only` (null when not given), `states` (the layer paths), `level`, `bro` and `box`, the effective values.

The game turns the bro only from `xI` and `left`/`right` (`CheckFacingDirection`), so the sweep sets it facing right when it freezes the clock and puts the original facing back at teardown. A companion, a `BoondockBro` whose `leadingBro` is the swept bro, is turned and put back with it, and turned again before each readback, since its own `Update` turns it back from an `xI` or `left` kept from before the freeze.

Right after freezing the clock the sweep records the whole bro: every instance field of every component under him, his own included; per object its active flag, layer and local transform; per renderer its enabled flag, material and that material's properties; per sprite its cell, size, offset and colour; and his ammo, which the HUD holds a copy of. All of it is put back when a state ends, after its `after` list too, and on an unload mid-sweep, so no state starts from what an earlier one left: a real special's held item, sheet swap, spent ammo or stealth layer stays on that state's own frames. The frames and their `written` flags are recorded first, and putting a cell back is no write, so a later state's untouched cell reads as it stood at sweep start and is still `carried`; `levelChanges` and `retired` are attached on the next `Update`, after the restore. The contents of a list he holds and anything outside him are out of reach: a static registry is what `after` is for, and the level is not restored, so after a level change he is put back over whatever is left, which `levelChanges` dates. A later cell can differ because of that, the last step of the melee states drawn airborne over a crater for one.

On the held clock `Time.timeScale` and `Time.deltaTime` are both 0, so code dividing by either gets 0/0. The mod keeps the game's own divisions by the clock at 0 whatever stopped it (`set_game_speed` in `tool-behaviour.md`), the camera's and the level clock's included, but not a custom bro's: his `SetDeltaTime` dividing by the clock would make `t` NaN, which his `Update` would add into his position, speed and every timer. A postfix on the bro's most-derived `SetDeltaTime` and `SetHighFiveBoostDeltaTime` puts a non-finite `t` back to 0 as it is computed, before anything reads it, so he proceeds on the held clock like any bro: the record gets `deltaRepaired: true` and no error. Every `Update` and `LateUpdate` the sweep checks each float, double, `Vector2` and `Vector3` field in that record and each transform under him: one that became non-finite is put back to its recorded value, while one already non-finite at sweep start is the bro's own sentinel and stays. A value put back lived through an `Update`, so the record gets `nonFinite`, a list of names (`x`; `<object>.<field>` for another component, `<object> transform`), and `capture.json`'s `errors` gets `state '<name>': <names> went non-finite on the frozen clock and was put back, so this state's frames are not to be trusted`, so the reply's `success` is false.

A state can also pin a flag an `Animate` method means to clear before it re-enters `ChangeFrame`, and that recursion never returns: the base `special_new` on Captain Ameribro, whose `AnimateSpecial` calls `ChangeFrame` with `specialFrame` past 10 and `usingSpecial` still pinned. The stack overflow is a SIGSEGV no `catch` sees, so a prefix on the bro's most-derived `ChangeFrame` counts its depth and past 16 levels skips the call and errors the state, which stops at that frame: `state '<name>': ChangeFrame re-entered itself 16 levels deep and would have overflowed the stack, so it was cut short and the state stopped at this frame`.

It resolves the player's character up front, so a player with no character fails the script at startup. A swap mid-sweep to a bro with a different GameObject name errors that state and every later one with `player <n> respawned as '<new name>', not the swept '<old name>', so the remaining states were not swept`; a gib does not replace the character on the held clock, so the remaining states error with `no character for player <n>`.
