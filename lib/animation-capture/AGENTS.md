# lib/animation-capture

The `AnimationCapture` script is the in-game half of `capture_animations`, and `states/` holds the bundled state lists. Being outside `scripts/`, neither appears in `list_scripts` or `list_test_scripts`.

## State lists

`base-states.json` covers the animations `TestVanDammeAnim` and `BroBase` share, which every stock or BroMaker bro inherits, except the dance and the gestures other than Flex, which the game never plays for a player's bro; those are in `unplayed-states.json`, layered after the base. A per-bro list (`drunken-broster.json` is the worked example) carries only its own states plus any base entry it must restate.

A file is a bare array of entries or an object with a `states` array; its other keys are documentation. Restate a whole entry, never a patch over the base one. Restate a base entry whenever the bro overrides its dispatch: `special_new` on a bro whose `AnimateSpecial` steps `usingSpecialFrame` instead of `frame` needs its own entry, or the base one drives a field the animation never reads.

The `setup` below is abridged.

```json
{
  "name": "running",
  "requires": { "useNewFrames": true },
  "setup": { "actionState": "Running", "ducking": false, "dashing": false, "health": 3, "gunFrame": 0 },
  "step": { "field": "frame", "values": [0, 1, 2, 3, 4, 5, 6, 7] },
  "expect": { "sheet": "main", "row": 2, "cols": [0, 7] },
  "note": "ChangeFrame's Running arm -> AnimateRunning; ..."
}
```

- **`name`** — required, unique; names the strip file and the report entry.
- **`setup`** — fields pinned on the character to steer `ChangeFrame` to this animation: booleans, numbers, or an enum member name as a string; any other shape is refused before the sweep. Names resolve against the character and its base classes, retried with a leading underscore (`frame` resolves to `_frame`). The whole bro is restored when the state ends, so name a field only to pin it. A state whose gun write `ChangeFrame` gates on `gunFrame <= 0` pins `gunFrame: 0`, so the step draws its gun cell rather than carrying it over.
- **`before`** / **`after`** — parameterless instance methods called on the character, for states reachable only by having it swap an object reference for itself (`running_holding_item` in `drunken-broster.json`). `before` runs once after `setup`, before the first step; `after` when the state ends, after the bro is restored and on error teardown, and the bro is restored again after it. `after` also undoes what real side effects left outside the bro, as `special_new` in `drunken-broster.json` calls `BecomeSober` for `DrunkenCameraManager`'s static list. An `after` that throws leaves the state captured, with the message as `afterError` and in `errors`.
- **`insert_before`** — on a layer entry, place the new state ahead of the named one, which must already be in the merged list; otherwise new entries append. Ignored when the entry restates a state already present.
- **`step`** — `field` (default `frame`) and the `values` to drive it through; countdown-driven animations name their own counter (`rollingFrames`, `flexSpecialFrame`, `gunFrame`, …). `setup` is re-applied before each value, so an animation that clears its own driving flag still runs its full span.
- **`step.call`**, **`step.before`**, **`step.after`** — methods called on every step right after `ChangeFrame` in the same frame, as the game's `Update` runs `RunGun`; `step.before` pins fields just ahead of the calls and `step.after` just after, all restored with `setup`. A call is a parameterless instance method or, on a state provided a zipline, one taking it (`AttachToZipline`). This draws cells written outside `ChangeFrame`: the firing states pin `gunFrame` one above the cell and `gunCounter: 0.04` (over `RunGun`'s 0.0334 threshold), call `RunGun`, then put `gunCounter` back to 0 so the bro's own `Update` does not step the gun again. A per-bro `RunGun` override is reached the same way.
- **`provide`** — `ladder` or `zipline`, an object the level would supply, present for the state's length. `ladder` is a `BoxCollider` on the `Ladders` layer where `IsNearbyLadder` probes, clear of the bro's ground rays; `zipline` an inactive `ZipLine` over the bro, pinned as `attachedToZipline` every step. Neither renders.
- **`expect`** — the cells the animation should address: `row`, and either an inclusive `cols` range walked one column per step in the order given (`[3, 0]` walks 3, 2, 1, 0) and as long as `step.values`, or `col`, held on every step. `row` and `col` are the sprite's `lowerLeftPixel` floor-divided by its own cell size, with no offset: take a new state's values off a capture run rather than deriving them. Only `row` and `col` are compared, so the right cells of a different texture still pass; read `texture`, `texId` and `texW`/`texH` in `capture.json` when a sheet swap is the point. A cell recorded `written: "carried"` never satisfies an expectation.
- **`expectGun`** — the same over the gun overlay; a state stating both matches only when both walks do.
- **`requires`** — layout flags that must hold on the live character (`useNewFrames`, `canAirdash`); otherwise the state is skipped, not errored.
- **`knownMismatch`** — reason a one-shot that clears its own flag on its last frame addresses less than its span. It excuses only the last step, and is ignored when `expectGun` failed or on a single-column span.
- **`lethal`** — `true` when entering the state reads as a death, with a non-empty `lethalReason`; anything else is refused before the sweep. Pinning `actionState: Dead` with `health: 0` calls neither `Death()` nor `ReduceLives()`, so the game takes no life and respawns nothing on the held clock; a BroMaker hero runs its own `OnDeath` when it sees `actionState` Dead.
- **`needsSideEffects`** — reason string, for a state whose frames only show when its calls run for real; any other value is refused before the sweep. Swept only with `allowSideEffects`, and with `includeLethal` too when also `lethal`.
- **`unsupported`** — reason, in place of `setup`/`step`, for an animation needing a reference only the world can supply or a path `ChangeFrame` never reaches. Keep such entries so the report shows the hole.
- **`note`** — where the dispatch and cell arithmetic live in the decompiled source, and known limitations. Cite code by member, never by line; unqualified members are `TestVanDammeAnim`'s.

## The capture script

- `Main()` re-checks readiness and refuses a pause, a cutscene, a dead, piloting or unreleased bro, one other than the requested `bro` by roster name, and a slot the claim rule (`lib/AGENTS.md`) says is held. The overlap probe adds one refusal, a renderer under a recalled rig; any other renderer in the crop is only recorded. A player with no character fails at startup.
- **The slot at the end**: `Finish()` replaces the sweep's `AppDomain` slot entry with a lease under the `claim` token, `outDir` kept, for `hold` seconds when both were given, and otherwise clears it; the server passes `hold` on a remote target, so the folder stays claimed while it fetches (`.claude/rules/remote.md`). An unload clears the slot only while it still holds the sweep's own entry.
- **Side-effect suppression** skips the swept bro's own `UseSpecial`, `UsePockettedSpecial`, `PerformKnifeMeleeAttack`, `PerformPunchAttack`, `Land`, `TriggerFlexEvent`, `FireWeapon` and `ReleaseHeldObject` through its most-derived declaration, and game-wide every overload of the `Map` and `MapController` methods that damage, kill or stun units, damage terrain, hatch alien eggs or deflect projectiles; a skipped call returns its type's default. Every shock wave `EffectsController.CreateShockWave` returns is retired through its own `EffectDie` rather than skipped, since `BroBase.Land` writes to it.
- **Rendering**: never `ReadPixels` off the backbuffer, which reads zeroed for seconds after a level load and whenever the window is not presented. Each step renders every screen camera, in depth order, into one `RenderTexture` and reads the crop from it. With `backdrop`, both of a frame's renders go through the backdrop render (`lib/AGENTS.md`) on one temporary camera kept for the sweep and tracked in `ScriptContext.GameObjects`, with the renderers classified once for the two.
- **Contribution check**: each on-screen frame is rendered again with the character's renderers off (the parts his snapshot found under him, so a child a state spawned is not his) and the crops compared. A frame with no differing pixel whose addressed cells are all transparent on the sheet is `cellEmpty`, not an error; any other `contributed: false` is a filed error, unless the state is already filed as `blank capture`, an on-screen strip that read back all zero (under `backdrop`, zero or the backdrop colour).
- **`written`**: a postfix on `SpriteSM.SetLowerLeftPixel` records who last moved each sprite between the step and the readback: `capture`, `game`, or `carried` (left over).
- **The bro is restored after every state**, and on an unload mid-sweep: every non-const, non-readonly instance field of every `MonoBehaviour` under him, each object's active flag, layer, transform and renderer state, each sprite's cell, size, offset and colour, and his ammo. Restoring a cell is no write, so an untouched cell still reads `carried`. Lists he holds and anything outside him are not restored: a static registry is what `after` is for, and the level is not restored, which `levelChanges` dates.
- **A state's error** from an exception ends `: <message> at <Type>.<Method>`, the method that threw, when the exception carries a trace; the whole trace is in the UMM log.
- **Facing**: the game turns the bro only from `xI` and `left`/`right`, so the sweep faces him right at the freeze and puts the facing back at teardown, with a `BoondockBro` companion led by him turned before each readback too.
- **The retire pass**, one frame after each state, retires what the held clock never lets animate out: pooled effects requested since the last cleanup, children under the bro outside his snapshot, and objects newly drawn across the state's crops. A pooled effect goes through its own `EffectDie`; anything else is deactivated, never destroyed. Units, cameras, reaction bubbles and the sweep's own object are kept. A left-over object still drawn in a state's first crop is that state's error.
- **`levelChanges`**: the whole map's blocks, units and doodads are snapshotted at sweep start and diffed at each retire pass, before anything is retired. A later state's cell can differ after a level change.
- **The held clock** makes `Time.timeScale` and `Time.deltaTime` 0. The sweep resets any clock game code sets (`clockDisturbed`, an error) every `Update` and `LateUpdate`. A postfix on the bro's most-derived `SetDeltaTime` and `SetHighFiveBoostDeltaTime` puts a non-finite `t` back to 0 (`deltaRepaired`, no error), since the mod's own zero-clock guard (`set_game_speed` in `.claude/rules/tool-behaviour.md`) does not cover custom bros. A recorded float or vector field or transform that goes non-finite is put back and errors the state (`nonFinite`); one non-finite at sweep start is the bro's own sentinel and stays.
- **`ChangeFrame` recursion**: a pinned flag an `Animate` method means to clear can make `ChangeFrame` re-enter itself forever, a SIGSEGV no `catch` sees, so a prefix on the bro's most-derived `ChangeFrame` cuts it past 16 levels and errors the state.
- **Scene change**: a level load or restart mid-sweep errors that state and every later one (`sceneChanged`) and skips the retire, leak and level passes. A mid-sweep swap or gib errors the remaining states.
- `capture.json` reads `complete: false` until its final write at the end, and is also written on an unload mid-sweep.
